## Post-Work Report

The work done today has seen the successful implementation of the intervention validation step for the shortcut MLP. This work ended up being spread across two sessions rather than one, but the final result now covers both the implementation of the intervention helper function and the integration of the intervention results into the main `compare_models.py` experiment.

The new `interventions.py` module contains a single helper function called `intervene_scaled_shortcut`. This function takes the already preprocessed data and creates a copied version of the selected split's `X_scaled` matrix with only the shortcut feature changed. The original processed data dictionary remains unchanged. This was an important design choice because the original test data should remain the reference point for comparison, while the intervened versions represent separate test-time conditions.

The intervention methods implemented are:

 - `zeroed`: set the scaled shortcut feature to `0.0`.
 - `noise`: replace the scaled shortcut feature with random normal noise.
 - `reversed`: multiply the scaled shortcut feature by `-1`.
 - `permuted`: shuffle the scaled shortcut values across the selected split.

Tests were also added in `test_interventions.py`. These tests check that the intervention outputs keep the same shape as the original input matrix, that the original processed data is not modified, that the shortcut column is changed as expected, and that the non-shortcut features remain unchanged. The permutation test also checks that the same shortcut values are retained after shuffling, which is important because the permuted condition should destroy the row-wise relationship without changing the overall shortcut distribution.

Alongside the intervention function, I also added a lower-level `summarize_lrp_relevance` helper to `explain.py`. The previous `summarize_mlp_lrp` function only worked directly on a processed data dictionary and selected split. This was useful for the normal test split, but it was less flexible for intervention validation because the intervention function returns a modified `X_scaled` matrix rather than a full processed data dictionary. The new helper solves this by summarizing already-computed LRP outputs and relevance tensors, so the normal and intervened conditions can be saved in the same format.

The `compare_models.py` script was updated to evaluate the already-trained shortcut MLP on the normal test split and on all four intervention variants. No new MLP models are trained for the interventions. Instead, the same trained shortcut MLP is reused, and only the test input matrix is changed. The script now saves the intervention metrics, the LRP summary for each condition, the shortcut relevance share, and the generated plots automatically.

### Intervention Metrics

The intervention results show that the shortcut MLP is highly sensitive to the shortcut feature. The normal shortcut test condition fails extremely badly, which is consistent with the expected behavior from the polynomial shortcut extrapolating beyond the train and validation region. When the shortcut is zeroed or replaced with noise, the test error becomes much smaller, although still worse than the clean MLP. When the shortcut is reversed, the model still fails strongly. When the shortcut is permuted, the result remains almost the same as the normal shortcut condition.

| Condition | MAE | RMSE | R2 | Shortcut relevance share |
|---|---:|---:|---:|---:|
| normal | 85347.7175 | 200119.5748 | -913519393.7794 | 0.7604 |
| zeroed | 15.7794 | 15.9427 | -4.7978 | 0.0000 |
| noise | 15.7366 | 16.8427 | -5.4709 | 0.1217 |
| reversed | 401.4865 | 685.3291 | -10712.6396 | 0.8091 |
| permuted | 85350.1627 | 200121.0512 | -913532872.8911 | 0.7360 |

The zeroed and noise conditions were especially useful because they show that removing or disrupting the shortcut can make the model's predictions far less extreme. This is slightly different from the most straightforward intervention validation story, where destroying an important feature would always be expected to make performance worse. In this project, the shortcut is already harmful on the test split because it extrapolates badly. Therefore, the more meaningful result is not that every intervention worsens performance, but that changing only the shortcut feature causes large changes in model behavior.

The reversed condition is also useful because it still receives high shortcut relevance and still produces poor predictions. This suggests that the model is still reacting strongly to the shortcut feature when the shortcut direction is flipped. The permuted condition is interesting because it remains almost as bad as the normal shortcut condition. A possible interpretation is that the shortcut values in the test split are already extremely large due to the polynomial extrapolation, so shuffling them across the test region preserves much of the harmful behavior.

Overall, these results support the interpretation that the shortcut MLP has learned to rely strongly on the artificial shortcut feature. The result should still be stated modestly: in this controlled synthetic setup, LRP assigns high relevance to the shortcut feature, and intervention tests show that changing this same feature meaningfully changes the model's predictions.

### Interpretation of Intervention Relevance

The relevance values under intervention should be interpreted as explanations of the model's behavior for each counterfactual input condition. This distinction is important because the intervention changes the input itself. In the zeroed condition, the shortcut relevance becomes zero because the shortcut column is set to `0.0` in scaled input space. This does not contradict the earlier result where the normal shortcut condition assigned high relevance to the shortcut feature. It instead shows that the explanation is local to the current input: once the shortcut is neutralized, the model's remaining prediction has to be explained through the other features and the learned parameters of the network.

The target-like but shifted shape in the zeroed and noise conditions suggests that the shortcut MLP did still learn some usable structure from the legitimate time-series features. The model saw `time`, `f_linear`, and `annual_seasonality`, so it was not trained only on the shortcut. However, because the shortcut was available during training, the learned relationship through the normal features appears to be poorly calibrated. When the shortcut is removed or replaced with centered noise, the model seems to fall back onto this weaker learned trend, which gives a curve that resembles the target but is still shifted and worse than the clean MLP.

This also helps explain why low relevance in a regression setting feels different from low confidence in a classification setting. The model is not "unsure" in the same way a classifier might be. It still has to output a continuous value. A better interpretation is that the shortcut-trained MLP may have learned some local regions where changes in the input features contribute only weakly to changes in the output. Since the current MLP uses ReLU activations, the learned function is piecewise linear. If a test region falls into a flatter part of that piecewise-linear function, the prediction can become nearly constant, and LRP may propagate little relevance back to the input features.

The normal and intervened relevance summaries therefore answer slightly different questions. The normal relevance summary asks what the model uses when the shortcut is present as generated. The intervention relevance summaries ask how the model explains its prediction after the shortcut has been modified. For a future experiment, it may be useful to compare this ReLU MLP with a similar MLP using smoother activation functions such as `tanh` or `sigmoid`. This would not necessarily solve the shortcut problem, but it could help test whether some of the flatter or low-relevance regions are partly connected to the piecewise-linear behavior of ReLU. This should be treated as a possible follow-up analysis rather than a requirement for the current intervention validation milestone.
