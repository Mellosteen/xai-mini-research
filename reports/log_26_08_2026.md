## Relevant Knowledge

### Layer-Wise Relevance Propagation

Layer-Wise Relevance Propagation (LRP) is a local explanation method that attempts to redistribute a model's prediction backward through the neural network and onto the input features. In the context of this project, the intention is to determine how much relevance is assigned to each input feature for a given MLP prediction.

For an input matrix

$$X \in \mathbb{R}^{n \times d},$$

where $n$ is the number of samples and $d$ is the number of input features, the relevance tensor returned for the input should have the same shape:

$$R \in \mathbb{R}^{n \times d}.$$

This means that each row corresponds to a single sample, and each column corresponds to one input feature. In the shortcut dataset, the columns are ordered as `time`, `f_linear`, `annual_seasonality`, and `shortcut_polynomial`, so the final column of the relevance tensor corresponds to the shortcut feature.

An important clarification is that relevance values are not probabilities and are not created by applying a softmax. They may be positive or negative, and their raw values do not necessarily sum to one. In order to compare the relative amount of relevance assigned to each feature, I used the mean absolute relevance:

$$\bar{R}_j = \frac{1}{n}\sum_{i=1}^{n}|R_{ij}|.$$

This can then be normalized into a relevance share:

$$S_j = \frac{\bar{R}_j}{\sum_{k=1}^{d}\bar{R}_k}.$$

This normalized relevance share is not part of LRP itself, but it is a useful summary statistic for this project because it allows the shortcut feature's relevance to be compared against the normal input features.

### Zennit Composites and Attributors

Zennit separates the LRP rule from the attribution procedure. The composite defines the backward relevance propagation rules that should be applied to the model's layers. For this first implementation, I used the `EpsilonPlus` composite, which applies the epsilon LRP rule to the MLP. The epsilon rule includes a small stabilizing term $\epsilon$ to reduce numerical instability when relevance is propagated through layers.

The attributor is the object that executes the explanation procedure. In this implementation, the `Gradient` attributor is used together with the `EpsilonPlus` composite. Without a composite, a standard gradient attributor would return ordinary gradient attribution, which measures local sensitivity:

$$\frac{\partial f(x)}{\partial x_j}.$$

With the LRP composite attached, the same backward-pass machinery is used, but the backward rules are replaced by LRP rules. Therefore, the returned tensor is interpreted as LRP-style input relevance rather than ordinary gradient sensitivity.

Since this project is a regression task, the MLP produces one scalar output per sample. This means that the backward pass should explain the scalar prediction for each sample, not select one class from a classification output. Unlike the examples in the Zennit documentation that use `torch.eye(...)` for class selection, this project uses `torch.ones_like(output)` through the attributor so that each regression output is explained.

### Scope of LRP

Zennit operates on PyTorch modules, so LRP is currently only applied to the MLP models. The linear regression and kernel ridge regression models remain useful as predictive baselines, but explaining them with Zennit would not fit the library's intended use. For the purposes of this project, this is acceptable because the main research question concerns whether a local XAI method can detect shortcut reliance in a neural time-series regression model.

## Post-Work Report

The implementation of the first explainability module has been completed. `explain.py` now contains an `explain_mlp_lrp` function which applies Zennit's `EpsilonPlus` composite to a trained PyTorch MLP model and returns both the model output and the input relevance tensor. The function accepts either a NumPy array or a PyTorch tensor as input, converts it into a detached tensor with gradient tracking enabled, and then uses Zennit's `Gradient` attributor to calculate LRP-style relevance values.

The returned relevance tensor has the same shape as the input matrix, which is the desired behavior for this stage of the project. This means that each feature receives a relevance value for each explained sample. The function has also been exported through the package's `__init__.py`, so it can be imported directly from `xai_mini_research`.

`test_explain.py` has also been implemented. The tests train a small MLP on a reduced synthetic dataset, run LRP on both the clean and shortcut versions of the data, and check that the output and relevance tensors have the expected shapes. Additional tests check that all relevance values are finite. 

The conceptual understanding from today's work is that LRP is not simply returning a probability distribution over features. Rather, it returns raw relevance values that can be summarized afterward. For the current project, the most useful first summary that should be implemented is the normalized mean absolute relevance per feature, with special attention given to the relevance share of `shortcut_polynomial`.

Overall, today's goal has been completed successfully. The project now has a first local explanation method for the MLP, which means the next natural step is to integrate these relevance summaries into the model comparison experiment and save them alongside the existing metrics. After that, intervention validation can be used to test whether high shortcut relevance actually corresponds to model failure when the shortcut is removed, corrupted, or otherwise made unreliable.
