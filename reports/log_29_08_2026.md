## Post-Work Report

The LRP integration has been implemented as a reusable `summarize_mlp_lrp` helper in `explain.py`. This function calls the existing `explain_mlp_lrp` method, keeps the per-sample LRP behavior available, and returns a compact summary of feature relevance for a selected split.

The summary records mean absolute relevance, mean signed relevance, normalized relevance share, total mean absolute relevance, output mean, output standard deviation, and the shortcut feature's relevance share when `shortcut_polynomial` is present.

`compare_models.py` now runs this summary for the baseline MLP and the shortcut MLP on the test split, then saves both summaries under `models.mlp.lrp` in the result JSON.

The newest comparison result shows the shortcut MLP assigning about 76.04% of normalized mean absolute relevance to `shortcut_polynomial` on the test split. This matches the expected Clever Hans pattern where the shortcut model has poor test behavior when the shortcut extrapolates badly, and LRP assigns high relevance to the shortcut feature.

## Supplementary LRP Notes

After the main LRP integration was complete, I explored a few visualizations for the per-sample relevance values. This was useful because the saved JSON summary shows the average behavior, but the LRP tensor itself is local and contains one relevance value per feature per sample.

The heatmaps were first plotted using normalized absolute LRP relevance share. This means each sample row shows how the total absolute relevance is split across the available input features. In the baseline MLP, `time` and `f_linear` receive most of the relevance, while `annual_seasonality` receives noticeably less relevance overall. This may be because `time` and `f_linear` are strongly redundant, since `f_linear = time * 0.02`, and the trend component explains much of the target. The seasonal feature may act more like a smaller correction, especially because the generated target uses an interaction-like term where annual seasonality is scaled by time.

This does not necessarily mean that the annual seasonality feature is useless. It may mean that the current MLP learns the dominant trend features more easily than the subtler periodic component. The network is also still intentionally small, so a deeper or wider model might learn the seasonal interaction more strongly. A future test could remove either `time` or `f_linear` and see whether the relevance assigned to `annual_seasonality` increases.

### LRP Line Maps

The LRP line maps were implemented to show the same normalized relevance shares over test time. These plots confirmed the same pattern as the heatmaps but made the transitions easier to understand.

![Baseline LRP line map](lrp%20line%20maps/lrp_line_base_29_08.png "Baseline LRP Line Map")

![Shortcut LRP line map](lrp%20line%20maps/lrp_line_short_29_08.png "Shortcut LRP Line Map")

For the baseline MLP, relevance is mostly split between `time` and `f_linear`, with `annual_seasonality` appearing as a smaller periodic contribution. For the shortcut MLP, the line plot shows three rough regions: an early region where relevance is mixed between normal features and the shortcut, a middle region where almost all propagated relevance collapses toward zero, and a later region where the shortcut feature receives nearly all normalized relevance.

The middle region was initially confusing, but it seems to be a genuine attribution result rather than a plotting error. The model output is almost constant in that region, so the MLP may be sitting in a flat ReLU behavior region where there is very little propagated relevance.

### Shortcut Prediction Scatter

The final exploratory visualization plots shortcut MLP predictions over the test split, with point color representing the normalized shortcut relevance share. A symmetric log y-axis was used because the shortcut model produces extremely large predictions in the test region.

![Shortcut prediction scatter](lrp%20shortcut%20scatters/lrp_short_scatter_29_08.png "Shortcut Prediction and Shortcut Relevance Scatter")

This plot makes the Clever Hans behavior especially visible. When the shortcut model begins producing extreme predictions, the points also become high in shortcut relevance. This supports the interpretation that LRP is not merely assigning high shortcut relevance in the aggregate, but is also identifying the same region where the model behavior breaks down.

## Next Step

The next step is intervention validation where I will create test-set variants where the shortcut is removed, replaced with noise, reversed, or permuted, then compare metric degradation to uncover whether the model truly overrelies on the shortcut feature.

### Removed shortcut

Upon testing, set the shortcut to some neutral value to "mask" the shortcut's presence / contribution.

### Noise shortcut

Upon testing, set the shortcut to just random noise to see if the model follows and mirrors the behavior of the produced random noise.

### Reverse shortcut

For testing, reverse the shortcut feature by multiplication of -1.

### Permuted shortcut 

For one or more features, we shuffle the values in their columns.
