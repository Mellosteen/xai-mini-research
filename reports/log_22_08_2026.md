## Today's Goals

This is the second work day on the project. The main goal is to begin implementing shortcut features into the synthetic time-series data so that future XAI experiments can test whether a model is learning the intended signal or a misleading shortcut.

Today's goals will be considered complete once the following tasks have been finished:
 - understand what a shortcut feature is in the context of this project.
 - decide on a first concrete shortcut mechanism for the synthetic time-series data.
 - implement a fourth (shortcut) feature in `generate_time_data` that can be enabled with `shortcut=True`.
 - add tests that assess the shortcut feature's shape, determinism, and intended failure behavior.

### Conceptual Notes

A shortcut feature is a feature that helps the model perform well under the observed training or validation setup, but does not represent the real underlying relationship we want the model to learn and predict. In this project, the intended relationship is the smooth time-series target produced from the linear trend and annual seasonality. A shortcut should therefore be a feature that predicts the target for the wrong reason.

My first shortcut idea is to add a fourth feature based on a high-degree interpolated polynomial fit to the target before the test split. This can be seen as a form of label leakage where the shortcut feature is built using target values from the observed period, so a model can use it as a means to easily learn the target. Because a high-degree polynomial extrapolates poorly outside the fitted time range due similar to Runge's phenomenon (bad fitting due to oscillation within input domain), the shortcut feature can produce extreme values in the test split. This should result in a meaningful Clever Hans experiment where the model may look strong when the shortcut works, but fail when the shortcut no longer matches the true unseen data in the test split.

Some Notes & Remarks:
 - If the shortcut fails already on validation data, validation metrics should catch it.
 - If the shortcut works on train and validation but fails on test, it better simulates a hidden shortcut that passes model training but breaks under distribution shift.

## Post-Work Report

The work done today has seen the successful implementation of the option to include a shortcut feature along with the ability to determine whether it should be fit on just the train split or train and validation splits in the time series data. The degree of the Chebyshev polynomial is also configurable. Corresponding tests on the structure of the data with the shortcut added have passed, and tests on the performances on each currently implemented model have shown promising results that the model is reacting to the shortcut feature, which has expectedly reduced their performance on the test data.

The shortcut feature was implemented by fitting a Chebyshev polynomial to the noisy target values over a selected observed range. In the main comparison experiment, the shortcut was fit over the train and validation splits with `shortcut_fit_split="train_val"` and `shortcut_deg=20`. This means the shortcut is allowed to behave well over the train and validation splits, while the test split is treated as an extrapolation region where the shortcut should no longer be reliable.

Tests were also added for the shortcut feature and model behavior:
 - `test_data.py` checks that the shortcut adds a fourth feature column, remains deterministic for the same seed, correctly records whether it was fit on train or train and validation, and raises errors for invalid shortcut arguments.
 - `test_linear.py`, `test_krr.py`, and `test_mlp.py` check how each model reacts when the shortcut is fit only on the training split or fit on both train and validation splits.

The `compare_models.py` script was updated to train baseline and shortcut versions of all currently implemented models. It now prints and saves metrics for the linear regression, kRR, and MLP models both with and without the shortcut feature. The plotting was also separated into a baseline plot and a shortcut plot to reduce visual clutter. Since the shortcut models can produce extremely large test predictions, the shortcut plot is zoomed to the target range so that the real target curve remains visible.

### Linear Regression
| Split | Baseline RMSE | Shortcut RMSE | Baseline R2 | Shortcut R2 |
|---|---:|---:|---:|---:|
| Train | 1.2934 | 1.2920 | 0.9928 | 0.9928 |
| Validation | 2.7967 | 2.5168 | 0.7497 | 0.7973 |
| Test | 3.6760 | 28532.6805 | 0.6918 | -18570506.7127 |

### Kernel Ridge Regression
| Split | Baseline RMSE | Shortcut RMSE | Baseline R2 | Shortcut R2 |
|---|---:|---:|---:|---:|
| Train | 0.0848 | 0.2160 | 1.0000 | 0.9998 |
| Validation | 0.1727 | 0.1997 | 0.9990 | 0.9987 |
| Test | 0.5799 | 63.6167 | 0.9923 | -91.3169 |

The baseline kRR model still slightly outperformed the shortcut kRR model on train and validation splits, but the shortcut version still showed a large test-time performance collapse. This suggests that the RBF kRR model may be more robust to the shortcut than the linear regression and MLP models, while still being harmed by the shortcut feature under extrapolation.

### MLP
| Split | Baseline RMSE | Shortcut RMSE | Baseline R2 | Shortcut R2 |
|---|---:|---:|---:|---:|
| Train | 0.4953 | 0.9230 | 0.9989 | 0.9963 |
| Validation | 1.0109 | 0.9532 | 0.9673 | 0.9709 |
| Test | 1.9101 | 200119.5748 | 0.9168 | -913519393.7794 |

The MLP shortcut model improved slightly on validation but failed extremely badly on the test split. This matches the intended behavior of the shortcut feature: it can appear useful when fit on train and validation data, but it becomes unreliable once the model is evaluated outside that fitted range.
